# داشبورد پایش درخواست‌ها — MVP

یک داشبورد وب فارسی و راست‌به‌چپ برای پایش و تحلیل درخواست‌های پشتیبانی و توسعه.

## وضعیت و اجزای پروژه

- **بک‌اند:** FastAPI، Pandas و Pydantic
- **فرانت‌اند:** React، TypeScript، Vite، ECharts و TanStack Table
- **منبع داده در نسخه MVP:** فایل Excel و برگه `ریز اطلاعات`
- **منبع داده در آینده:** PostgreSQL، از طریق همان قرارداد Repository

```text
request-dashboard-mvp/
├── backend/                 # API و خواندن داده Excel
│   ├── app/
│   ├── data/
│   └── requirements.txt
└── frontend/                # رابط کاربری داشبورد
    ├── src/
    └── package.json
```

## پیش‌نیازها

روی ویندوز این موارد باید نصب باشند:

- Python 3.11، 3.12 یا 3.13: `python --version`
- Node.js 18 یا جدیدتر: `node --version`
- npm (همراه Node.js نصب می‌شود): `npm.cmd --version`

دستورها را از پوشه ریشه پروژه اجرا نکنید؛ برای بک‌اند وارد `backend` و برای فرانت‌اند وارد `frontend` شوید.

> مثال‌های اصلی این راهنما برای **Command Prompt (CMD)** هستند. اگر از PowerShell استفاده می‌کنید، بخش مخصوص PowerShell را ببینید.

## داده Excel

فایل زیر باید موجود باشد:

```text
backend/data/پایش کل درخواست ها MASTER.xlsx
```

بک‌اند فقط برگه `ریز اطلاعات` را می‌خواند و برگه `ریز اطلاعات 2` را، چون تکراری است، ترکیب نمی‌کند.

اگر فایل Excel جای دیگری قرار دارد، فایل `backend/.env.example` را با نام `backend/.env` کپی کنید و مقدار `EXCEL_FILE_PATH` را به مسیر فایل خود تغییر دهید. در صورت تغییر نام برگه نیز `EXCEL_SHEET_NAME` را تغییر دهید.

### به‌روزرسانی فایل توسط کارفرما

کارفرما می‌تواند فایل Excel را در همان مسیر جایگزین یا ذخیره کند. بک‌اند در هر درخواست فقط زمان و اندازه فایل را بررسی می‌کند و تنها در صورت تغییر واقعی فایل، داده را دوباره می‌خواند؛ در غیر این صورت همان snapshot حافظه را بازاستفاده می‌کند. برای نمایش سریع داده جدید و گزینه‌های فیلتر تازه، در داشبورد دکمه `بروزرسانی داده‌ها` را بزنید.

برای جلوگیری از خواندن فایل نیمه‌ذخیره‌شده، بهتر است فایل جدید ابتدا با یک نام موقت ذخیره و سپس جایگزین فایل اصلی شود.

## اجرای پروژه در ویندوز (CMD)

### 1. اجرای بک‌اند

یک پنجره CMD باز کنید و دستورهای زیر را اجرا کنید. به‌جای مسیر نمونه، مسیر واقعی پوشه پروژه خودتان را وارد کنید.

```bat
cd /d H:\work\Projects\EDR_Dashboard\request-dashboard-mvp\backend
python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

پس از دیدن پیام آماده‌بودن سرور، این پنجره را باز نگه دارید. سپس این نشانی‌ها را بررسی کنید:

- سلامت سرویس: <http://127.0.0.1:8000/health>
- مستندات تعاملی API: <http://127.0.0.1:8000/docs>

### 2. اجرای فرانت‌اند

یک پنجره CMD **جدید** باز کنید و اجرا کنید:

```bat
cd /d H:\work\Projects\EDR_Dashboard\request-dashboard-mvp\frontend
npm.cmd install
npm.cmd run dev
```

آدرس نمایش‌داده‌شده توسط Vite را در مرورگر باز کنید؛ معمولاً این آدرس است:

```text
http://127.0.0.1:5173
```

فرانت‌اند به API بک‌اند در `http://127.0.0.1:8000/api` متصل می‌شود؛ بنابراین بک‌اند باید قبل از باز کردن داشبورد در حال اجرا باشد.

## اجرای آسان با دابل‌کلیک

برای استفاده روزمره کارفرما، روی فایل `start-dashboard.bat` دابل‌کلیک کنید. این فایل در اولین اجرا، در صورت نیاز محیط Python و وابستگی‌های Node.js را نصب می‌کند و سپس دو پنجره برای API و رابط کاربری باز می‌کند. در اجراهای بعدی فقط سرویس‌ها را بالا می‌آورد.

پس از اجرا، آدرس‌های زیر در پنجره فایل نمایش داده می‌شوند:

- `http://127.0.0.1:5173` برای استفاده روی همان رایانه
- `http://IP-نمایش‌داده‌شده:5173` برای استفاده روی تلفن همراه در همان Wi-Fi مورداعتماد

برای توقف برنامه، در هر دو پنجره بازشده کلیدهای `Ctrl + C` را بزنید. اگر Windows Firewall اجازه دسترسی در شبکه Private را پرسید، فقط در شبکه خصوصی و مورداعتماد آن را تأیید کنید.

## استفاده با تلفن همراه در شبکه محلی

1. رایانه کارفرما و تلفن را به یک Wi-Fi یا شبکه LAN مورداعتماد وصل کنید.
2. روی رایانه، `start-dashboard.bat` را اجرا کنید.
3. آدرس `Phone on the same trusted Wi-Fi` را که فایل نمایش می‌دهد، در مرورگر تلفن باز کنید.
4. پنجره‌های API و UI را باز نگه دارید؛ با بستن آن‌ها برنامه متوقف می‌شود.

آدرس را کامل و در نوار آدرس مرورگر وارد کنید، برای نمونه `http://172.24.12.249:5173`؛ آن را در موتور جست‌وجو جست‌وجو نکنید. لانچر IP رابطی را نمایش می‌دهد که route پیش‌فرض شبکه دارد تا آداپتورهای مجازی مانند VirtualBox انتخاب نشوند.

رابط برای صفحه موبایل واکنش‌گرا است: فیلترها تک‌ستونه می‌شوند، نمودارها زیر هم قرار می‌گیرند و جدول قابل اسکرول افقی باقی می‌ماند.

## توقف سرویس‌ها

در پنجره‌ای که هر سرویس را اجرا کرده‌اید، کلیدهای `Ctrl + C` را بزنید.

اگر پنجره اجرای سرویس را بسته‌اید، ابتدا شناسه پردازش (PID) را پیدا کنید:

```bat
netstat -ano | findstr :8000
netstat -ano | findstr :5173
```

شماره انتهای خطی که `LISTENING` دارد همان PID است. سپس آن پردازش را متوقف کنید:

```bat
taskkill /PID شماره_PID /F
```

پورت `8000` برای بک‌اند و پورت `5173` برای فرانت‌اند است.

## خطاهای رایج

### `uvicorn is not recognized`

محیط مجازی فعال نشده یا وابستگی‌ها نصب نشده‌اند. در پوشه `backend` این دستورها را اجرا کنید:

```bat
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

استفاده از `python -m uvicorn` تضمین می‌کند نسخه نصب‌شده در همان محیط مجازی اجرا شود.

### لانچر هنگام `Preparing the Python environment` متوقف می‌شود

نسخه جدید `start-dashboard.bat` علت دقیق را نشان می‌دهد. ابتدا مطمئن شوید Python 3.11، 3.12 یا 3.13 از [python.org](https://www.python.org/downloads/windows/) نصب شده و در زمان نصب گزینه `Add Python to PATH` فعال شده است. سپس یک CMD جدید باز کرده و این دستور را اجرا کنید:

```bat
python --version
```

اگر نسخه نمایش داده نشد، پایین‌تر از 3.11 بود یا `3.14` بود، Python 3.13 را نصب کنید. اگر پیام خطا مربوط به نصب packageها و `pypi.org` بود، اتصال اینترنت، proxy سازمان و محدودیت antivirus را بررسی کنید؛ نصب اولیه به دانلود packageها نیاز دارد و IT باید دسترسی HTTPS به `pypi.org` و `files.pythonhosted.org` را مجاز کند.

### خطای `WinError 10013` یا اشغال بودن پورت `8000`

احتمالاً یک بک‌اند دیگر روی پورت `8000` اجرا شده است. یا همان سرویس در حال اجرا را استفاده کنید، یا مطابق بخش «توقف سرویس‌ها» پردازش آن پورت را متوقف کرده و دوباره بک‌اند را اجرا کنید.

### Vite به‌جای `5173` از `5174` استفاده می‌کند

پورت `5173` اشغال است. سرویس فعلی را متوقف کنید یا در `backend/.env` مقدار `CORS_ORIGINS` را برای پورت جدید نیز اضافه کنید، سپس بک‌اند را یک‌بار راه‌اندازی مجدد کنید:

```text
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://localhost:5174,http://127.0.0.1:5174
```

### خطای پیدا نشدن فایل Excel یا برگه

نام فایل، مسیر `backend/data/` و نام برگه `ریز اطلاعات` را بررسی کنید. در صورت نگهداری فایل در محل دیگر، `EXCEL_FILE_PATH` و `EXCEL_SHEET_NAME` را در `backend/.env` تنظیم کنید.

## امنیت و استقرار شبکه

اجرای محلی با `127.0.0.1` فقط روی همان رایانه قابل دسترسی است. برای استفاده در شبکه سازمان، API را مستقیماً با HTTP در اختیار کاربران قرار ندهید؛ یک reverse proxy مانند IIS یا Nginx با گواهی TLS معتبر در جلوی فرانت‌اند و بک‌اند قرار دهید و فقط URLهای HTTPS را به کاربران بدهید. این کار از شنود و دستکاری ترافیک در شبکه جلوگیری می‌کند.

در محیط production این تنظیمات را در `backend/.env` قرار دهید و سرویس را راه‌اندازی مجدد کنید:

```text
CORS_ORIGINS=https://dashboard.example.com
ALLOWED_HOSTS=dashboard.example.com
FORCE_HTTPS=true
```

همچنین در `frontend/.env` آدرس HTTPS مربوط به API را مشخص کنید:

```text
VITE_API_BASE_URL=https://dashboard.example.com/api
```

پروژه اکنون فقط originهای صریح، متدهای `GET` و `POST` و هدر `Content-Type` را برای CORS می‌پذیرد، cookie اعتباری را فعال نمی‌کند و هدرهای پایه امنیتی پاسخ را اضافه می‌کند. احراز هویت و سطح‌بندی دسترسی هنوز بخشی از MVP نیست و در صورت قرار گرفتن داشبورد در معرض شبکه غیرقابل‌اعتماد باید جداگانه اضافه شود.

### نکته مهم درباره شبکه محلی

حالت تلفن همراه برای راحتی استفاده در **شبکه محلی مورداعتماد** طراحی شده و از HTTP استفاده می‌کند؛ پس آن را روی Wi-Fi عمومی، اینترنت یا شبکه‌ای که افراد غیرمجاز به آن دسترسی دارند فعال نکنید. برای جلوگیری از شنود یا تغییر ترافیک خارج از LAN باید reverse proxy با HTTPS و گواهی معتبر، و ترجیحاً احراز هویت، راه‌اندازی شود.

## راهنمای انتقال و راه‌اندازی اولیه برای کارفرما

1. پوشه کامل `request-dashboard-mvp` را به رایانه کارفرما منتقل کنید؛ پوشه `backend/data` و فایل Excel داخل آن را حتماً حفظ کنید.
2. Python 3.11، 3.12 یا 3.13 و Node.js 18 یا جدیدتر را نصب کنید و یک‌بار رایانه را باز و بسته کنید.
3. روی `start-dashboard.bat` دابل‌کلیک کنید. در بار اول اتصال اینترنت برای نصب وابستگی‌ها لازم است.
4. پس از نمایش آدرس، داشبورد را روی همان رایانه یا تلفن همراه باز کنید.
5. برای به‌روزرسانی داده‌ها، فایل Excel را با همان نام در `backend/data` جایگزین و در داشبورد دکمه `بروزرسانی داده‌ها` را بزنید.
6. برای اجرای بعدی، فقط `start-dashboard.bat` را دابل‌کلیک کنید؛ نصب دوباره لازم نیست.

در صورت نیاز به ساخت آیکون، روی `start-dashboard.bat` راست‌کلیک کرده، `Send to > Desktop (create shortcut)` را انتخاب کنید و نام میانبر را «داشبورد پایش درخواست‌ها» بگذارید.

## بهینه‌سازی و امنیت در کد

- `backend/app/repositories/excel_repository.py`: فایل Excel با زمان آخرین تغییر و اندازه فایل fingerprint می‌شود؛ تا وقتی فایل تغییر نکرده باشد دوباره از دیسک خوانده نمی‌شود. قفل `RLock` نیز از بازخوانی هم‌زمان جلوگیری می‌کند.
- `backend/app/services/request_service.py`: ستون‌های محاسباتی، گزینه‌های فیلتر و snapshot آماده داده cache می‌شوند و فقط پس از تغییر فایل دوباره ساخته می‌شوند. نمودار جدید `technicians` نیز با شمارش برداری Pandas ساخته می‌شود.
- `frontend/src/App.tsx`: جست‌وجوی فیلتر فقط برای گزینه‌های زیاد فعال است (به‌استثنای ماه)، دارک‌مود در `localStorage` ذخیره می‌شود و نمودارها رنگ‌های مناسب تم فعال را دریافت می‌کنند.
- `frontend/src/api.ts`: API به‌طور پیش‌فرض از hostname همان صفحه استفاده می‌کند؛ بنابراین باز شدن داشبورد با IP رایانه روی تلفن، خودکار به API همان رایانه متصل می‌شود. در production می‌توان URL HTTPS را با `VITE_API_BASE_URL` تنظیم کرد.
- `backend/app/main.py` و `backend/app/core/config.py`: محدودسازی CORS و hostهای مجاز، محدودیت متدها و هدرها، حذف credential cookie و هدرهای `X-Content-Type-Options`، `X-Frame-Options` و `Referrer-Policy` اعمال شده‌اند. گزینه `FORCE_HTTPS` نیز برای استقرار پشت reverse proxy وجود دارد.
- `start-dashboard.bat`: لانچر محلی، API و Vite را فقط برای استفاده روی رایانه و LAN مورداعتماد اجرا می‌کند و IP تلفن را نمایش می‌دهد.
